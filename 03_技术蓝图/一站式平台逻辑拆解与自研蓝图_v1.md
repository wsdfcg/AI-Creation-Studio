# 一站式 AI 短剧平台 · 潜藏逻辑拆解与自研蓝图 v1

> 版本：v1（2026-10-02）｜目的：为将来自研一站式部署做架构准备
> 素材来源：天工短剧 Agent 实战（2026-10-01/02 对话全记录）+ ArcReel / DramaClaw 开源实现反推
> 一句话定位：**"会用工具"是执行层，**"会造工具"**是把工具潜藏的逻辑机械化。**

---

## 一、为什么要拆（目标）

我们现在的处境：用天工/小云雀当执行层，把资料按它们的流程喂，赚"方法论差价"。但用户的目标不止于此——**有钱了，自己部署一站式平台**。那时候需要的不再是"怎么喂料"，而是"平台内部每个环节在干什么、为什么这么干、用什么技术实现"。

本文把三层逻辑抓出来：
1. 天工这次实战暴露的**对话式逻辑链**（它每一步在做什么）
2. 开源平台（ArcReel / DramaClaw）的**流水线架构**（共性模块 + 技术选型）
3. 我们 23 个 skill 方法论 → 平台模块的**映射与差距清单**

## 二、天工实战逻辑链拆解（9 层）

这次对话天工吃下剧本后，一步步的行为，每步都在做一件事：

| 层 | 天工行为 | 它在做什么（潜藏逻辑） | 我们对应 skill |
|---|---|---|---|
| 1 解析 | 读剧本→输出"项目制作基准"（类型/时代/画幅/色调/光线/质感/禁用元素） | **风格基准锁定**：先定全片不可变参数，后面所有生成都引用它 | director-storyboard §5.5 色温表 + prompt-engineering |
| 2 资产提取 | 输出角色资产（视觉设定/服装状态）、场景资产（含建议新拆）、道具资产（含作用/待确认项） | **资产清单自动抽取**：从剧本文本里结构化抽出角色/场景/道具 | assets-library + world-building |
| 3 理解 | 输出"人物关系与戏剧功能"（谁是谁的什么、烟包=线索） | **故事图（story graph）**：建立角色关系网络，供后续分镜引用 | drama-script-doctor |
| 4 诊断 | 建议：场次合并/空间关系统一/茶舍视觉锚点/门缝眼睛处理/钢笔刻字待补 | **结构诊断**：主动找剧本缺陷并给改法（不是被动执行） | story-comprehension + drama-script-doctor |
| 5 节奏 | 段落节奏分配（前5-10%抛危险/转场慢/盘问中快/卡点极短） | **节奏规划**：按付费短剧节奏模板分配段落时长 | director-storyboard §3.7 |
| 6 连续性 | 输出"必须保持"清单（角色服装链/道具生命周期/视觉/雨线） | **连续性锁定前置**：生成前先把不可漂移项锁死 | consistency-engine |
| 7 镜头设计 | 关键段落镜头方向（开场特写链/盘问正反打/接棒安静段） | **镜头语言预设计**：把情绪转成镜头方案 | director-storyboard 运镜公式 |
| 8 补全 | 主动问 5 个参数（时长/对白/刻字/参考图/画面倾向） | **对话式补全**：信息不全时先问齐再出分镜，不硬猜 | （我们缺这个，靠人工问） |
| 9 输出 | 37 镜分镜稿 + 时长核对 + B-roll 标注 + 连续性约束总结 | **结构化产出**：分镜表即数据结构，后续提示词/首尾帧/资产引用全部挂在镜号上 | director-storyboard + 分镜表模板 |

**关键洞察①**：天工不是一个"生成器"，是一个**有状态的知识引擎**——它先建立（风格基准+资产+关系+节奏）四套上下文，再一次性产出分镜。每一步的输出都是下一步的输入（数据流），不是孤立生成。

**关键洞察②**：它的分镜稿自带"审计"（时长核对表、B-roll 标注、连续性总结）——这和我们 qc-review / 预算硬闸是同一逻辑，平台把它做成了**自动伴随校验**。

**关键洞察③**：我们的 23 个 skill **覆盖了它 9 层里的 8 层方法论**（除第 8 层对话式补全）——但我们是"人肉流水线"（人读 skill 文档再操作），它是"机械流水线"（代码自动串联）。**差距不在方法论，在机械化。**

## 三、开源平台共性架构（ArcReel / DramaClaw 反推）

### 3.1 ArcReel（开源，Claude Agent SDK 多智能体）["https://gitee.com/yonja/ArcReel","https://followagents.com/en/agents/arcreel","https://arc-reel.com/zh/"]

```
用户 → 主 Agent（状态感知：读 project.json + 文件系统，决策下一步）
          ↓ 编排 Skill（manga-workflow）
          ├── analyze-characters-clues（全局角色/线索提取）
          ├── split-narration-segments（旁白分段）
          ├── normalize-drama-script（剧本规范化）
          ├── create-episode-script（分集剧本）
          └── asset-generation（资产生成，含角色设计图）
          ↓
ImageBackend / VideoBackend / TextBackend（多供应商抽象层）
= Veo 3.1 / Seedance / Grok / Sora 2 / Vidu / 阿里百炼（OpenAI 兼容）
```

核心设计：
- **Subagent 上下文隔离**：每个子任务独立处理大段原文/参考图，只回传精炼摘要 → 主 Agent 上下文不爆炸，能跑完整部长篇小说，**中断可从任意阶段恢复**
- **Character DNA 前置**：分镜渲染前先扫描全文建角色 DNA → 跨镜头一致性
- **project.json 状态管理**：整个项目是一个可查询状态文件，任意阶段可读可续
- 技术栈：React 19 + FastAPI + Claude Agent SDK

### 3.2 DramaClaw（开源，Python，通用 AIGC 视频引擎）["https://heatdrop.ai/repo/dramaclaw/dramaclaw","https://topairepos.com/repos/dramaclaw/dramaclaw","https://freeaitool.com/en/image-tools/ai-short-drama-production-pipeline-open-source/"]

```
小说手稿 → 解析器 → story graph（角色/关系/时间线可查询网络）
  → 章节切分 + beat 规划（自适应/直译/舞台三模式 + 审查修复循环）
  → beat 驱动分镜 + 首帧（线稿草图系统：先线稿确认构图 → 再渲染，前后景分层+角色占位）
  → 情感感知配音（可切换供应商）
  → 合成（字幕/SRT/全片）
```

核心设计：
- **story graph**：剧本不是一行行文本，是"角色/关系/时间线"网络，任何环节可查询——这和天工第 3 层（人物关系）完全同构
- **线稿先验（虾导）**：先出线稿草图确认构图，再渲染最终图——**和我们的 director-storyboard §3.6 构图参考图同一逻辑**
- **审查修复循环**：每阶段带 review & repair loop——**和我们 qc-review 同一逻辑**
- **确定性生产**：声称"确定性"——即同一输入稳定产出，不抽卡
- Docker 一键部署、推理全走远程 OpenAI 兼容网关（本地无 GPU）、成本低至 20 元/分钟

### 3.3 共性模块表（两家 + 天工取交集）

| 模块 | 天工 | ArcReel | DramaClaw | 我们对应 |
|---|---|---|---|---|
| 输入解析（剧本→结构化） | ✅ | ✅（subagent） | ✅（story graph） | drama-script-doctor |
| 风格基准锁定 | ✅ | ✅（全局） | ✅ | director-storyboard §5.5 |
| 资产提取（角色/场景/道具） | ✅ | ✅（asset-generation） | ✅ | assets-library |
| 人物关系图 | ✅ | ✅（characters-clues） | ✅（story graph） | world-building |
| 分集/beat 规划 | ✅（段落节奏） | ✅（episode-script） | ✅（beat planning） | director-storyboard §3.7 |
| 分镜生成 | ✅（37镜表） | ✅ | ✅ | director-storyboard |
| 构图先验（线稿/参考图） | ✅（要参考图） | ✅ | ✅（线稿草图） | §3.6 构图参考图 |
| 连续性锁定 | ✅ | ✅（DNA 前置） | ✅ | consistency-engine |
| 自动伴随校验（时长/连续性） | ✅ | ✅ | ✅（review loop） | qc-review + greenlight |
| 对话式补全 | ✅ | ✅（主 Agent 问） | ✅（交互层） | ❌ 缺 |
| 状态管理（断点恢复） | ✅（画布） | ✅（project.json） | ✅ | ❌ 缺 |
| 多供应商网关 | ✅（自有） | ✅（Backend 抽象） | ✅（OpenAI 兼容） | model-router（方法论） |
| 交互审核层（导演角色） | ✅（Agent） | ⚠️ | ✅（小夏导演） | ❌ 缺（人是审核） |

**结论**：行业标准流水线已经收敛到同一套 13 模块架构。**我们的方法论覆盖其中 9 个**，缺 4 个执行层能力（对话补全/状态管理/多供应商网关代码/交互审核层）。

## 四、我们的 skill 方法论 → 平台模块映射（已有资产盘点）

| 模块 | 我们已有（方法论文档） | 缺什么（机械化） |
|---|---|---|
| 剧本解析 | drama-script-doctor（钩子/卡点/对白≤15字） | 缺"剧本→JSON 结构"的解析器代码 |
| 风格基准 | director-storyboard §5.5 色温表 | 缺"基准配置文件"（project.json 的 style 段） |
| 资产提取 | assets-library（资产卡/评级/版本） | 缺"剧本→资产清单"自动抽取 |
| 分镜生成 | director-storyboard 运镜公式 + 节奏模板 | 缺"基准+资产→37镜分镜表"生成器 |
| 提示词 | prompt-engineering 六段式 | 缺"分镜行→六段式提示词"模板渲染器 |
| 连续性 | consistency-engine 硬闸 | 缺"跨镜引用校验"代码（首尾帧绑定） |
| QC | qc-review L1/L2/L3 | 缺"视频→自动抽帧→比对"自动化 |
| 预算 | greenlight-analyst 硬闸 | 缺"生成前费用计算/生成中记账"代码 |
| 模型路由 | model-router §1.6 Tool Gate | 缺"供应商 API 统一抽象层"（ArcReel Backend 模式） |

## 五、自研蓝图

### 5.1 目标架构（13 模块 → 4 层 + 2 横切）

```
┌─ 交互层 ─────────────────────────────┐
│ 对话式导演 Agent（补全/审批/追问）      │  ← 天工 Agent / DramaClaw 小夏导演
├─ 编排层 ─────────────────────────────┤
│ 主 Agent：读 project.json → 决策下一步 → 派发   │  ← ArcReel 编排 Skill 模式
│ 状态管理：project.json（可断点恢复）           │
├─ 生产层（9 模块流水线）──────────────┤
│ 剧本解析 → 风格锁定 → 资产提取 → 关系图      │
│ → beat 规划 → 分镜生成 → 构图先验 → 连续性 → QC │
├─ 执行层 ─────────────────────────────┤
│ 供应商网关（OpenAI 兼容抽象：文/图/视频/配音）   │  ← ArcReel Backend 模式
│ = Seedance / 可灵 / Veo / 通义 / text_to_audio │
└─────────────────────────────────────┘
横切：预算闸（每步记账）｜ 合规闸（备案/AI标识）
```

### 5.2 技术选型方向（参考两家开源）

| 层 | 选型 | 依据 |
|---|---|---|
| 编排 | Claude Agent SDK（ArcReel 验证）或 LangGraph / Coze / Dify | 开源可自部署、支持 Subagent 上下文隔离 |
| 后端 | FastAPI（ArcReel 验证） | 轻量、异步、Python 生态 |
| 前端 | React（ArcReel 验证，可后置） | 成熟、多供应商 UI 组件多 |
| 状态 | project.json + 文件系统 / SQLite | 单机可跑，断点恢复 |
| 供应商 | 统一 OpenAI 兼容抽象层 | 换模型不换代码（我们的 model-router 方法论直接落地） |
| 部署 | Docker Compose（两家都是） | 2 核 4G 起步，推理全远程 |

### 5.3 路线图（先半自动 → 后全自动 → 再平台化）

| 阶段 | 做什么 | 成本 | 现在能做吗 |
|---|---|---|---|
| **P0 半自动管线** | 用 LLM 把我们的 skill 文档串成"提示词链"：剧本→分镜表→提示词→首尾帧需求，人工验收每步 | ≈0（豆包/火山额度） | ✅ **现在就能启动** |
| **P1 模块机械化** | 把 9 个模块写成可调用函数（解析器/分镜生成器/提示词渲染/一致性校验），LLM 只是执行体 | 低（开发时间） | 有钱后 |
| **P2 编排层** | 主 Agent + project.json 状态管理 + 断点恢复 | 中 | 有钱后 |
| **P3 平台化** | Web UI + 多项目 + 交互审核层 + 多用户 | 高 | 有团队后 |

### 5.4 与现役工具的关系（自研不是推翻）

- 自研完成前：天工/小云雀 = **验证器**（它的产出是我们的验收对象，它的流程是我们蓝图的参照）
- 自研完成后：它们的执行层被替换，**我们的方法论（skill）原样搬进平台**——因为平台 13 模块里 9 个我们早有方法论

## 六、差距清单（从"会用"到"会造"缺什么）

| # | 差距 | 优先级 | 怎么补 | 花钱吗 |
|---|---|---|---|---|
| 1 | skill 是文档不是程序（最大差距） | P0 | 把关键流程（剧本解析/分镜生成/提示词）先写成"可复制提示词链" | 不花 |
| 2 | 缺结构化状态（project.json） | P1 | 建项目目录规范 + 状态文件模板 | 不花 |
| 3 | 缺 LLM 编排层 | P1 | 学 ArcReel 的 Claude Agent SDK 模式 / 用 Coze/Dify 先试 | 少 |
| 4 | 缺供应商网关代码 | P1 | 按 model-router 方法论实现统一抽象层 | 不花 |
| 5 | 缺对话式补全模块 | P2 | 按天工第 8 层逻辑做"参数确认清单" | 不花 |
| 6 | 缺前端/交互层 | P3 | 后置，先用 CLI/对话式 | 花 |

## 七、下一步行动（现在就能做，不用等钱）

1. **P0 半自动管线启动**：把这套逻辑先跑一遍——用 LLM 把"剧本 v3 → 分镜 v2 → 每镜提示词 → 首尾帧需求"串成可复制的提示词链，人工验收（这也是天工正在帮我们做的，正好对照）
2. **沉淀模板**：把天工 37 镜分镜稿的"表头结构"存为我们的分镜表模板（已是 v2 基准）
3. **对照验证**：ArcReel / DramaClaw 的 13 模块表存进 repo，每完成一集，回来对照一次，看平台逻辑还有哪些我们没抓到
4. **攒差距清单**：每次用天工/小云雀发现新行为，登记进本文件第三节/第六节——**这就是我们自研的"需求文档"在长出来**
